# Debug Prompt: Beyond Presence Avatar Not Speaking — Streaming Latency Issue

**Date:** 2026-05-30  
**Author:** Engineering  
**Status:** 🔴 Unresolved — streaming synthesis turn still returns empty response  

---

## Problem Statement

We have a FastAPI backend that integrates with **Beyond Presence** (an avatar video-call platform) as a custom OpenAI-compatible LLM endpoint. The avatar speaks using text generated by our RAG pipeline (Anthropic Claude + Neo4j vector search).

**Observed behaviour:**  
During a live Beyond Presence call, the user's speech is transcribed correctly and appears on screen. However, **the avatar produces no audio response at all** — it just sits silently. Simple greetings ("hello") and complex questions ("what is MiFID II?") both produce silence.

**Backend logs confirm** the endpoint is being reached:
```
INFO: 34.65.9.187:0 - "POST /v1/chat/completions HTTP/1.1" 200 OK
```

**Root cause identified:**  
The full RAG pipeline (embed query → vector search → Claude tool-use turn → Claude synthesis turn) takes **20–25 seconds**. Beyond Presence almost certainly has a response timeout shorter than this. By the time our endpoint returns, BP has already given up and discarded the response — hence the avatar says nothing.

---

## Architecture Overview

```
User speaks
    ↓ STT (Beyond Presence)
    ↓ POST /v1/chat/completions  (OpenAI-compatible)
    ↓
FastAPI (api/main.py) → run_agent (api/agent.py)
    ↓
Turn 1: Claude decides to call search_knowledge tool     (~5s blocking)
    ↓
Tool execution: Neo4j vector search + embedding          (~5s blocking)
    ↓
Turn 2: Claude synthesises answer from retrieved chunks  (~10s blocking)
    ↓ total: ~20-25s
Beyond Presence receives response → avatar speaks
```

## What We've Tried

### Attempt 1: `asyncio.to_thread` for blocking calls
**File:** `api/agent.py`  
Wrapped `client.messages.create(...)` and `run_tool(...)` in `asyncio.to_thread()` so the FastAPI event loop is not blocked.

**Result:** The event loop stays alive, but this does NOT reduce first-token latency. All 20-25 seconds still elapse before the first byte reaches Beyond Presence. This is because the total work (two Claude calls + one vector search) still takes the same wall-clock time; we just freed the event loop while waiting.

### Attempt 2: Greeting fast-path
**File:** `api/agent.py`, `_GREETING_RE` regex  
Added a regex to detect simple greetings (`hi`, `hello`, `hey`, etc.) and respond **immediately** with a canned message, bypassing the full RAG pipeline entirely.

**Result:** ✅ Works perfectly. "Hello" now responds in **< 0.5 seconds**. Beyond Presence avatar speaks immediately for greetings.

```python
_GREETING_REPLY = (
    "Hello! I'm the SIX Corporate Advisor, powered by the Company Brain. "
    "I can answer questions about MiFID II, SFDR, EU Taxonomy, FATCA, and other "
    "regulatory frameworks. What would you like to explore today?"
)
```

### Attempt 3: Always stream `/v1/chat/completions`
**File:** `api/main.py`  
Removed the non-streaming response path and forced all responses through `StreamingResponse` with `text/event-stream`, so Beyond Presence gets chunks as they arrive.

**Result:** ⚠️ Partially correct but not enough. The first chunk still doesn't arrive until all 20-25 seconds have elapsed because all streaming chunks are emitted AFTER the full tool-use pipeline completes in the current non-streaming agent loop.

### Attempt 4: Two-phase streaming — stream the synthesis turn
**File:** `api/agent.py`  

**Architecture attempted:**
1. **Phase 1 (non-streaming):** Ask Claude with tools → get `tool_use` blocks. Non-streaming is needed here because we must see the full tool call specification before we can execute the tools.
2. **Execute tools:** Run `search_knowledge` via Neo4j vector search.
3. **Phase 2 (streaming):** Call `client.messages.stream(...)` WITHOUT the `tools` parameter (to force a text answer). Bridge the sync stream iterator into the async generator via a thread + `asyncio.Queue`.

**The `asyncio.Queue` bridge pattern:**
```python
token_queue: asyncio.Queue = asyncio.Queue()

def _sync_stream_wrapper(client, params, token_queue, loop):
    with client.messages.stream(**params) as stream:
        for text_chunk in stream.text_stream:
            loop.call_soon_threadsafe(token_queue.put_nowait, ("token", text_chunk))
        # ... collect final message ...
        loop.call_soon_threadsafe(token_queue.put_nowait, ("done", (stop_reason, content)))

fut = loop.run_in_executor(None, _sync_stream_wrapper, client, params, token_queue, loop)

while True:
    kind, payload = await token_queue.get()
    if kind == "token":
        yield Token(text=payload)
    elif kind == "done":
        break
```

**Why this was expected to work:** `client.messages.stream` is Anthropic's native streaming SDK. Its `.text_stream` iterator yields each token as it's generated on Anthropic's side. By pushing tokens into the queue in real-time from a background thread, the async generator can yield them to FastAPI's `StreamingResponse` immediately — first token in ~2-3 seconds.

**Current bug:** The streaming synthesis call (`Phase 2`) is returning an **empty response** — only `data: [DONE]` with no chunks before it.

**Test confirming the bug:**
```bash
curl -s -X POST http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"What is MiFID II in one sentence?"}],"stream":true}' \
  --max-time 50 | head -6

# Output:
# data: [DONE]
```

**Errors encountered during fixing:**
- `messages.3: tool_use ids were found without tool_result blocks` — Anthropic API error. Caused by passing stale conversation state (without tool results appended) into the streaming call. Fixed by snapshotting `list(convo)` AFTER tool_results are appended.
- Still getting empty response after fix — unknown root cause.

## Hypotheses for Why Phase 2 Returns Empty

1. **The `tools_executed` branch is never reached.** The non-streaming Turn 1 might already return `stop_reason = "end_turn"` (not `"tool_use"`) if Claude decides not to call a tool. The `if msg.stop_reason != "tool_use"` guard breaks out of the loop before `tools_executed` is set to `True`.

   - **How to verify:** Add logging to confirm whether Claude's Turn 1 actually returns `tool_use` or goes straight to `end_turn`.
   - **Possible cause:** The system prompt might be too directive and cause Claude to answer without searching knowledge.

2. **`loop.call_soon_threadsafe` is called from inside `run_in_executor` on the same loop.** This might cause a deadlock or silent drop if the thread's event loop reference is stale.

3. **The Anthropic streaming SDK `text_stream` iterator yields nothing** if the model returns an empty text block (e.g., it returns only a `tool_use` block with no text). This would make the queue receive `("done", ...)` with no preceding tokens.

4. **Exception in `_sync_stream_wrapper` being swallowed.** If an error occurs inside the `try` block after `("error", ...)` is queued, but before `("done", ...)` is queued, the `while True` loop in the coroutine breaks on `"error"` and never sees `"done"`. But since `("done", ...)` is queued in the `finally` block, this should be fine.

## What a Fix Should Look Like

The ideal solution is to use a **single streaming call from Turn 1**, using Anthropic's streaming SDK with tool support. The `anthropic` Python SDK supports streaming with tools via `client.messages.stream(tools=[...])`. During streaming:

- Text tokens arrive and can be yielded immediately.
- Tool-use blocks are buffered until the stream ends.
- After the stream, tool calls are executed and a second streaming call is made for synthesis.

Alternatively, a simpler immediate fix: **add a short pre-response** before the RAG pipeline runs, e.g.:

```python
# Immediately yield an acknowledgement token so BP starts the avatar
yield Token(text="Let me look that up for you... ")
# Then run full RAG pipeline
```

This would give BP a token within ~0.1 seconds, keeping the avatar alive while the 20s pipeline runs.

## Constraints

- **Anthropic SDK is synchronous.** `client.messages.create` and `client.messages.stream` are both blocking. They must be run in a thread (`asyncio.to_thread` or `run_in_executor`) when called from an async context.
- **`client.messages.stream` uses a context manager** (`with client.messages.stream(...) as stream`). It cannot be `await`-ed directly.
- **FastAPI `StreamingResponse` requires an async generator.** Tokens must be yielded from an `async def` function.
- **Anthropic conversation rules:** Messages must strictly alternate `user`/`assistant`. `tool_use` blocks in an assistant message must be immediately followed by a `user` message containing matching `tool_result` blocks.
- **Beyond Presence timeout:** Unknown exact value, but empirically < 15 seconds. First token must arrive within this window.
- **The localtunnel URL changes each session.** After each restart, `/api/register-agent` must be called with the new public URL to re-register the external API config with Beyond Presence.
